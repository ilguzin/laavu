# Как участвовать

Спасибо, что хотите помочь. Laavu на ранней стадии, поэтому перед большой работой лучше сначала открыть issue и обсудить: замысел может расходиться с тем, что кажется очевидным по коду.

## Что пригодится

- **Ошибки** — issue по шаблону: версия (`laavu version`), ОС сервера, браузер и устройство, шаги, что ожидали и что получили. Вывод `sudo laavu diag` очень помогает, но перед вставкой просмотрите его: там имена агентов и адрес сервера.
- **Предложения** — issue с описанием задачи, которую вы решаете, а не только решения.
- **Исправления** — pull request. Небольшие правки (опечатки, документы, очевидные ошибки) можно присылать сразу.
- **Уязвимости** — не в issue, см. [`SECURITY.md`](SECURITY.md).

## Окружение

Сборка, тесты, режим разработки и тестовая ВМ описаны в [`docs/dev.md`](docs/dev.md). Коротко:

```sh
make web build   # клиент и бинарники в bin/
make test        # go vet и go test, нужны tmux и git
make e2e         # Playwright против laavud dev
```

`bin/laavud dev` поднимает демон и воркер в одном процессе от текущего пользователя, без root и без входа, на `http://localhost:7700`.

## Pull request

- Одна задача — один PR. Рефакторинг отдельно от изменения поведения.
- `make test` проходит. Если менялся клиент или протокол — и `make e2e`.
- Новое поведение покрыто тестом: Go-тест рядом с кодом или сценарий в `test/e2e/tests`. Воркер и демон тестируются на настоящем tmux, вместо Claude Code — заглушка `test/fakeclaude`.
- Изменили установку, изоляцию или юниты systemd — прогоните `make vm-e2e` на тестовой ВМ или напишите в PR, что не прогоняли.
- Код форматируется `gofmt`, клиент проходит `tsc --noEmit` (`npm run build` в `web/`).
- Если поведение заметно меняется, обновите документ в `docs/`, который его описывает.

## Стиль

- Код и комментарии — как в окружающем коде. Комментарии и документы на русском, идентификаторы на английском.
- Без новых зависимостей без нужды: сервер — один статический бинарник без cgo, клиент должен оставаться лёгким для телефона.
- Демон не получает root и не хранит то, что можно взять у tmux, агента или файловой системы.
- Сообщения коммитов — в стиле [Conventional Commits](https://www.conventionalcommits.org/): `fix(worker): …`, `feat(web): …`, `docs: …`.
